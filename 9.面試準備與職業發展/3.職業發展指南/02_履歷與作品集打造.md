## 1. 履歷標準格式

### 1.1 歐美版(reverse-chronological,1 頁)

```
[姓名] | LLM / AI Engineer
San Francisco, CA | email | github.com/xxx | yourdomain.dev
─────────────────────────────────────────────
SUMMARY (3 行,可選)
LLM application engineer with 4 yrs SWE experience. Shipped production RAG over 10M docs serving
1K QPS at <2s p99. Open-source maintainer of phantom-mesh (2K+ stars).

EXPERIENCE
[Company] — Senior LLM Engineer                              2024-06 ~ present
- Designed and shipped multi-tenant RAG pipeline cutting hallucination rate 38% (eval: RAGAS faithfulness 0.62 → 0.86).
- Migrated inference stack from vLLM 0.5 to SGLang, reducing p99 latency 1.8s → 720ms.
- Led 3-engineer team building agent eval harness; now blocks regressions on every PR.

[Previous Company] — Software Engineer                       2021-08 ~ 2024-05
- ...

EDUCATION
B.S. Computer Science, [University], 2017-2021

OPEN SOURCE
- phantom-mesh (maintainer): multi-agent runtime, 2K stars. Wrote provider fallback layer.
- Contributor to LangChain, LiteLLM (5+ merged PRs).

SKILLS
LLM: OpenAI / Anthropic / Gemini API, RAG, agent orchestration, vLLM, SGLang, LangGraph, MCP
Lang: Python, TypeScript, Rust (intermediate)
Infra: Kubernetes, Postgres + pgvector, Redis, Docker
```

**核心原則**:
1. **量化、量化、量化** — 每個 bullet 帶數字(latency、QPS、cost、accuracy、users)。
2. **動詞開頭** — Designed / Shipped / Reduced / Led,不要 "Worked on..."。
3. **STAR 簡寫** — bullet 內隱含 situation → action → result,result 放最後。
4. **1 頁原則** — senior 也只給 1 頁,有特殊例外才 2 頁(博士、20 年經驗、轉職劇變)。
5. **不要照片、不要年齡、不要婚姻狀態**(歐美履歷一律拿掉)。

### 1.2 台灣版(本土慣例)

- **長度**:1–2 頁可接受。
- **照片**:多數台灣 HR 仍預期附照片(可放 LinkedIn-style 半身)。新創 / 外商可不放。
- **學歷可放前面**(尤其應屆 / 第一份)。
- **語言能力**(英、日、TOEIC / TOEFL)寫清楚。
- **104 / CakeResume 版需另寫一份**(欄位制限制較多)。

## 2. LLM 工程師履歷的「殺手項目」3 類

履歷上不需要 10 個項目。**2–3 個高質量的就贏 10 個 tutorial-level**。
2026 年最能擊穿面試官的三類:

### 2.1 End-to-end RAG(80% 的人都做,要做出差異)

- **不要做的**:用 LangChain template + 一份 PDF → "我做了一個 chatbot"。
- **要做的**:
  - 真實規模(>10 萬 chunks 或多租戶)
  - 至少 hybrid search(BM25 + vector)+ rerank
  - 完整 RAGAS / DeepEval eval pipeline,有量化指標
  - 有 latency budget(P50 / P99)、有 cost 追蹤
  - 有 fallback(retrieval 失敗時的行為)
- **可寫成**:"Built RAG over 5M Reddit comments, hybrid (BM25+E5) + Cohere rerank, RAGAS faithfulness 0.84, p99 1.2s, cost $0.003/query。"

### 2.2 Agent / Multi-agent 系統

- **不要做的**:單一 ReAct chatbot。
- **要做的**:
  - 至少 3 個 tool 的 agent,有真實外部 API
  - **長 horizon**(>20 steps),有 checkpoint / resume
  - **有 cost cap、有 error recovery**
  - 多 agent 協調(supervisor pattern / handoff)
- **phantom-mesh 範例**:provider router(OpenAI / Anthropic / Gemini fallback)、SSE
  streaming parser、跨平台 build chain — 都是面試現場可以講 30 分鐘的素材,因為 **真實
  做過會被連環追問,假的撐不過第 3 個 follow-up**。
- 可寫成:"Co-built phantom-mesh multi-agent runtime: provider abstraction layer handling
  fallback across 5 providers, SSE streaming with retry, cost tracking per-agent。"

### 2.3 訓練 / 微調自己的模型

- **入門版**:LoRA 微調 Qwen / Llama,做 instruction tuning 或 domain adaptation。
- **進階版**:GRPO / DPO 自訓 reasoning model;繼續預訓練(continued pretraining)做 domain LLM。
- **量化重點**:dataset size、training 小時、GPU 用量、eval score(MMLU / domain bench)、loss curve 圖。
- **可寫成**:"Fine-tuned Qwen2.5-7B with LoRA (r=16) on 50K customer support tickets;
  domain accuracy 64% → 89%; deployed via vLLM, p99 380ms。"

### 殺手項目共通檢查

每個項目要能回答:
1. **規模**(多少資料 / 多少 user / 多少 QPS)?
2. **指標**(latency、accuracy、cost)?
3. **trade-off**(為什麼選 A 不選 B)?
4. **失敗 / 學到什麼**(沒有失敗的項目都是假的)?
5. **下一步會怎麼改**?

## 3. GitHub 經營

### 3.1 README 寫法(讓陌生人 60 秒看懂)

```markdown
# project-name
> One-liner 解釋這個 repo 做什麼(不要超過 15 個字)。

[![CI](badge)] [![License](badge)] [![Stars](badge)]

## ✨ Features
- 3–5 個 bullet,每個一句話。

## 🚀 Quick Start
```bash
pip install xxx
xxx --demo
```
< 30 秒就能跑起來。

## 🎬 Demo
[Demo GIF or Video — 必備]

## 📐 Architecture
[ASCII 圖 or Mermaid]

## 📊 Benchmarks
[數字表格]

## 🤝 Contributing
...
```

### 3.2 必備元素

- **Demo GIF / 影片**:文字不如動態,30 秒最佳。可用 [asciinema](https://asciinema.org/)、
  [terminalizer](https://github.com/faressoft/terminalizer)、OBS。
- **可重現性**:`docker run`、`pip install` 或 `uv run` 一句話起來。沒人會花 30 分鐘 setup 你的 repo。
- **架構圖**:ASCII 或 Mermaid,別放 PowerPoint 截圖。
- **issue / PR 模板**:看起來成熟。
- **CHANGELOG.md**:有版本紀錄表示認真維護。
- **CI badge**:綠的 CI 是基本誠意。
- **License**:沒 license 等於沒人敢用。

### 3.3 commit message

- 用 [Conventional Commits](https://www.conventionalcommits.org/):`feat:` / `fix:` / `docs:` / `refactor:`。
- 面試官會抽看你的 commit 歷史 — `Update file.py` 連發 50 個是大紅燈。

## 4. 作品集網站

### 4.1 為什麼需要

- LinkedIn 太擁擠、GitHub 太工程師。**自己的網站是「給 PM / hiring manager / recruiter 看的版本」**。
- SEO 加成:面試官搜你名字第一個跳出來的是自己的網站,而不是隨機新聞。

### 4.2 最低可行作品集

1. **Domain**:`yourname.dev` / `.ai` / `.io`(年付 ~$15)。
2. **平台**:Vercel + Next.js / Astro / Nuxt 部署,免費。
3. **頁面**:
   - Home:一段 self-intro + 3 個 highlight project card。
   - Projects:每個項目一頁 case study(see §4.3)。
   - Writing:blog / 技術筆記。
   - About + 聯絡資訊。
4. **加分**:在每篇 case study 文章底部加 "Available for hire" CTA。

### 4.3 Case Study 結構(每篇 1500-3000 字)

```
1. TL;DR(150 字):做了什麼、結果、為什麼有趣。
2. Problem:當初為什麼做這個。
3. Architecture:架構圖 + 關鍵設計決策。
4. Technical Deep Dive:1–2 個最難的子問題深入講。
5. Results:量化指標、screenshot、demo link。
6. What I'd Do Differently:示坦誠 + 學習力。
7. Code / Repo link。
```

## 5. Public Learning(在 X / LinkedIn 持續發文)

### 5.1 為什麼有效

- **2026 hiring 50%+ 透過 LinkedIn / X DM,而不是 JD 投遞**。一個有 5K followers 的 AI eng,recruiter 主動找你的速度遠超你投履歷。
- **複利**:寫 1 篇技術文 24 小時內可能 0 互動,但累積 50 篇後會被 Google、被同行收藏、被獵頭看到。

### 5.2 發什麼?「3:2:1 原則」

- **3 次「我學了什麼」**:讀完一篇 paper、跑通一個工具、解決一個 bug 的紀錄。
- **2 次「我做了什麼」**:project update、demo gif、open source PR。
- **1 次「我的觀點」**:對某個技術趨勢的看法(可能引戰但會有人記住你)。

### 5.3 平台選擇

| 平台 | 受眾 | 適合內容 |
|---|---|---|
| X / Twitter | 國際同行、研究員、startup founder | thread、demo gif、hot take |
| LinkedIn | 台灣 / 亞洲 HR、recruiter、PM | case study、carousel、職涯反思 |
| Medium / Substack | 長文讀者、SEO | 教學、深入分析 |
| 個人 blog (Vercel) | 你自己的 SEO 主場 | 全部 |

### 5.4 「我沒東西可發」破解

- 把今天踩到的一個 bug + 解法寫成 300 字 → 已經比 90% 的人多。
- 把 paper 摘要翻成中文 + 一張圖 → 已經比 95% 的中文圈多。
- 一週 1 篇,維持 6 個月,就會有人主動聯絡你。

## 6. 面試前的「最後 24 小時」清單

### 24 小時前(前一天晚上)
- [ ] 重看自己履歷:每個 bullet 都能講出 1 分鐘故事?
- [ ] 重看 JD,標出 3 個關鍵字 → 對應自己的 2 個例子。
- [ ] 看面試官 LinkedIn:他們的背景、最近發的文。
- [ ] 公司近 1 個月新聞(產品發表、融資、PR),準備 2 個 "Why us" 切角。
- [ ] 準備 5 個 reverse question(問面試官的)。
- [ ] 確認 Zoom / Meet link、ID、視訊背景、耳機、網路備援。

### 12 小時前(當天早上)
- [ ] 重看 [`03_行為面試_STAR_範例.md`](./03_行為面試_STAR_範例.md) 的 Top 5 LLM 工程師問題。
- [ ] 跑一次自己最得意的 demo,確認 demo 能 work。
- [ ] 暖手:做 1 題 LeetCode medium,或寫 30 行 prompt engineering。
- [ ] 喝水、上廁所、深呼吸。

### 1 小時前
- [ ] 關閉所有 notification、Slack、IDE。
- [ ] 重看一次 STAR 答案的 30 秒 elevator pitch。
- [ ] 開 IDE 準備好可能要 live coding 的環境(若有)。
- [ ] 倒一杯水放在手邊。

### 結束後 30 分鐘內
- [ ] 寫 thank you email(senior 級必備,junior 級加分):3 句話 + 提到具體的一個對話點。
- [ ] 自己記錄一份「面試 retrospective」:被問了哪些題、哪題沒答好、下次怎麼改。
