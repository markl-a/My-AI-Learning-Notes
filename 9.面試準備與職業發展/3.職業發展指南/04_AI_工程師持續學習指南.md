## 1. 每週訂閱(週末花 90 分鐘掃過)

> 訊源不在多,在「signal-to-noise 高」。下面 5 個都是 2026 年我會推薦的核心訊源。

| 訊源 | 形式 | 為什麼訂 | 平均週時間 |
|---|---|---|---|
| **Epoch AI** | 報告 / blog | 量化 AI 進展 — compute、parameters、benchmark trend。不是觀點,是數據 | 15 分 |
| **SemiAnalysis** | 訂閱制長文 | 半導體 + AI infra 的深度分析 — H100/H200/B200/TPU/Blackwell、HBM 供需 | 20 分 |
| **Dwarkesh Podcast** | 1-3 hr 訪談 | 訪問 Anthropic / OpenAI / DeepMind 核心研究員,內容質量遠超主流媒體 | 30-60 分(可加速 1.5x) |
| **TLDR AI** | 每日 email | 5 分鐘掃完當天重要新聞 / paper / tool。被 spam 的時候訂這個就夠 | 5 分 × 5 = 25 分 |
| **Anthropic Economic Index** | 季度 / 報告 | Claude usage 資料分析「AI 在哪些任務上被 adoption」,業界佔有率最透明的訊號 | 隨更新 |

### 加分訊源(挑 1-2 個)

- **The Pragmatic Engineer**(Gergely Orosz):非 AI-only,但 AI hiring / 薪資 / 大廠動態深入。
- **Latent Space**(Swyx):AI engineer 社群中心,週報 + podcast。
- **arxiv-sanity-lite**:篩過的 arXiv 新 paper feed。
- **Hacker News(關 AI 標籤)**:留 5 分鐘看頭 5 條的留言區,常有比文章更精彩的內幕。
- **X / Twitter**:跟 30 人(挑研究員、infra 工程師,不要跟 AI hype 帳號)。

## 2. 每月習慣(每月底花一個週末做)

### 2.1 讀 1-2 篇 frontier paper

- **挑選來源**:
  - arXiv 每月「Top 5 cited (last 30 days)」on Papers with Code。
  - DeepLearning.AI / The Sequence 月 highlight。
  - 自己 follow 的研究員 / org repost。
- **讀法(quick read,1 hr / paper)**:
  1. Abstract + intro + conclusion(15 分):是否值得繼續?
  2. Figures + tables(15 分):結果怎麼樣?
  3. Methods 重點(20 分):跟我做過的比有什麼不同?
  4. 寫 5 行筆記到自己的 paper notes(10 分)。
- **2026 必讀清單範例**(候選):
  - GRPO / DAPO 系列(reasoning model 訓練)
  - Diffusion LLM(早期效率突破)
  - Long context / context engineering 相關
  - VLA(Vision-Language-Action)機器人模型
  - Sparse / mixture-of-expert 後續

對應 repo 章節:[`../../2.深入LLM模型工程與LLM運維/`](../../2.深入LLM模型工程與LLM運維/) 與
[`../../5.AI研究前沿_2024-2025/`](../../5.AI研究前沿_2024-2025/)。

### 2.2 跑 1 個新工具 demo

每月選一個 2025-2026 出現的新工具,花 2-4 小時跑通 hello world + 1 個自己的小 use case。
**不是讀文章,是手動跑**。

候選清單(可從這裡挑):

| 工具 | 類別 | 為什麼值得跑 |
|---|---|---|
| SGLang | 推論引擎 | RadixAttention 對 agent 場景有顯著加速 |
| vLLM 最新版 | 推論引擎 | 業界事實標準,要熟 |
| LangGraph | agent orchestration | 比 LangChain 適合 stateful workflow |
| Claude Agent SDK | agent SDK | Anthropic 官方,2026 後 enterprise 主流之一 |
| OpenAI Agents SDK | agent SDK | OpenAI 官方版 |
| Pydantic AI | LLM framework | 強型別 LLM 應用框架,2026 升溫 |
| MCP servers | tool integration | Anthropic MCP 已成 de facto agent-tool 協定 |
| Marimo | reactive notebook | 取代 Jupyter 的 2026 新選擇 |
| uv | Python 套件管理 | 取代 pip / poetry,實際快 10-100x |
| DeepEval / Promptfoo | LLM eval | eval-driven dev 的工具棧 |

### 2.3 寫 1 篇 public 文章

可短可長(300-2000 字),選一個本月學到的 / 解決的 / 觀察的點寫出來。
平台:個人 blog / LinkedIn / X thread / Medium。**累積比質量重要**,持續 6 個月後會有複利。

## 3. 每季習慣(每 3 個月做一次)

### 3.1 看一場 AI 大會錄影

整場 keynote + 自己挑 3-5 個 talk,通常一個週末可解決。
2026 年值得看的大會:

- **NeurIPS / ICLR / ICML**:學術主場,看 keynote + best paper talk。
- **OpenAI DevDay / Anthropic Build Day / Google I/O / Microsoft Build**:廠商策略 + 新 API。
- **NVIDIA GTC**:硬體 + AI stack 全景。
- **AI Engineer Summit / Latent Space Demo Day**:工程實作分享。
- **Strange Loop / Papers We Love**(已停辦但 archive 還在):深度技術。

看完寫 1 頁筆記:**哪 3 個 idea 我會在下季工作中應用**。

### 3.2 回顧本 repo 22 主題地圖

打開 [`../../2024-2026_AI完整領域全景圖.md`](../../2024-2026_AI完整領域全景圖.md),問自己:

1. 過去 3 個月,我在 22 個主題中深耕了哪些?(廣度檢查)
2. 哪些主題我自認 "夠用",但其實已 1 年沒更新?(過時檢查)
3. 下一季我要主動投入哪 2-3 個主題?(計畫)

### 3.3 履歷與 LinkedIn 更新

即使沒有要跳,每季也更新一次:
- 新做的 project 寫進去。
- 量化新數字(latency 改善、cost 降低、bench 進步)。
- 移除已過時的技能。
- 看 LinkedIn 上 senior LLM eng 的 profile,對比自己缺什麼。

## 4. 與本 repo 22 主題地圖的搭配策略

本 repo 的全景圖列了 22 個主題,**沒人能全精通**,正確玩法是:

### 4.1 用全景圖維持廣度

每個主題保持「能跟業界對話」的水準:
- 知道核心概念與術語。
- 知道有哪些主流工具 / 模型。
- 知道目前 SOTA 大約在哪裡。
- **花費**:每主題每季 ~2 hr 掃 README + 全景圖更新。

### 4.2 選 2-3 主題深耕

依職涯方向選:
- **AI Engineer**:LLM 應用工程(#3)、Agent(#13)、RAG(#10)、Harness(#14)。
- **ML Engineer**:LLM 核心訓練(#2)、Synthetic Data(#19)、AI 硬體(#11)、推論引擎(#14)。
- **Research-leaning**:推理模型(#4)、Causal ML(#17)、AI4Science(#12)、Self-Improving(#22)。
- **Application-leaning**:Generative UI(#20)、Voice(#14)、Robotics(#13)。

**深耕標準**:
- 能寫 paper-quality blog 文章。
- 能在 meetup 講 30 分鐘的內容。
- 至少有一個自己的 open source 貢獻 / 個人專案。
- 認識 5+ 個該領域的人(line / X / Slack)。

### 4.3 每年微調

每 12 個月做一次「方向 review」:當初選的 2-3 主題還是熱的嗎?有沒有新興主題冒出來?
2024 年選 RAG 是對的、2025 年 agent 開始接管、2026 年 reasoning model + context
engineering 是新熱點 — 沒人能一次選到底。

## 6. 防止 burnout 的學習節奏

學習力 ≠ 強迫看完所有訊息。維持下面三個底線,長線可以撐 10 年:

1. **不要每天追新聞**:每天追會焦慮,週末批次處理就夠。
2. **動手 > 看影片**:看 1 小時教學不如跑 30 分鐘 demo。
3. **接受「我沒跟上」**:每年有 50+ 個新工具新模型新 paper,sane 的人本來就只追自己 fit 的方向。看到陌生詞不要 panic,記下來、有需要再深入。

## 7. 一張時間預算表(供參考)

| 頻率 | 時長 | 內容 |
|---|---|---|
| 每天 | 5-10 分 | TLDR AI / 看 X timeline / 看 Hacker News |
| 每週 | 90 分 | 訂閱訊源掃過 |
| 每月 | 1 個週末(8 hr) | 讀 paper + 跑 demo + 寫文章 |
| 每季 | 1 個週末(8 hr) | 看大會 + repo 主題 review + 更新履歷 |
| 每年 | 1 週 | 方向大 review + 規劃下一年主題 |

**總時間**:約佔工作時間 10-15%。維持 3 年,你會發現自己已經是同 cohort 的前 10%。
