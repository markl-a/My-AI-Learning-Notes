# 9.4 任務特定基準

## 📊 概述

任務特定基準針對具體應用場景設計，提供更精準的評估。與通用基準不同，這些基準專注於特定領域的能力，更貼近實際應用需求。

---

## 1. 問答系統 (Question Answering)

### 📋 主要基準

#### 1.1 SQuAD (Stanford Question Answering Dataset)

**基本資訊：**
- **版本**：SQuAD 1.1, SQuAD 2.0
- **任務**：閱讀理解，從段落中找出答案
- **資料量**：100K+ 問題

**SQuAD 1.1：**
- 所有問題都有答案
- 答案必在給定段落中

**SQuAD 2.0 改進：**
- 增加無法回答的問題（約 1/3）
- 測試模型識別「無答案」的能力

**示例：**
```
段落：
Albert Einstein was born in Ulm, Germany in 1879. He developed the
theory of relativity, one of the two pillars of modern physics.

問題：Where was Einstein born?
答案：Ulm, Germany

問題（SQuAD 2.0）：When did Einstein win the Nobel Prize?
答案：Unanswerable（段落中沒有此資訊）
```

**評估指標：**
```python
from datasets import load_dataset
from transformers import pipeline

# 載入資料集
squad = load_dataset("squad_v2")

# 評估指標
def evaluate_squad(predictions, references):
    exact_match = 0
    f1_scores = []

    for pred, ref in zip(predictions, references):
        # Exact Match
        if normalize_answer(pred) == normalize_answer(ref):
            exact_match += 1

        # F1 Score（token 級別）
        f1 = compute_f1(pred, ref)
        f1_scores.append(f1)

    em = exact_match / len(predictions) * 100
    f1_avg = sum(f1_scores) / len(f1_scores) * 100

    return {"EM": em, "F1": f1_avg}

# 典型性能
# BERT-base: EM ~80%, F1 ~88%
# GPT-4: EM ~85%, F1 ~92%
```

#### 1.2 Natural Questions (NQ)

**特點：**
- 來自真實 Google 搜索查詢
- 更開放、更自然的問題
- 包含長答案和短答案

**示例：**
```
問題：how many episodes in season 4 of the crown

短答案：10
長答案：The fourth season of The Crown consists of 10 episodes...
```

#### 1.3 TriviaQA

**特點：**
- 650K 問答對
- 強調世界知識
- 提供多個證據文檔

**難度對比：**
```
SQuAD:     閱讀理解能力（答案在段落中）
NQ:        搜索 + 理解能力
TriviaQA:  知識廣度 + 推理能力
```

### 🎯 開放域 vs 封閉域 QA

| 特性 | 封閉域 QA | 開放域 QA |
|------|-----------|-----------|
| **輸入** | 問題 + 相關文檔 | 僅問題 |
| **答案來源** | 給定文檔 | 模型內部知識 |
| **評估難度** | 較簡單 | 較困難 |
| **實際應用** | 企業文檔問答 | 通用知識問答 |
| **代表基準** | SQuAD | TriviaQA, NQ |

## 2. 機器翻譯 (Machine Translation)

### 📋 主要基準

#### 2.1 WMT (Workshop on Machine Translation)

**基本資訊：**
- 年度競賽（自 2006 年）
- 多語言對（英語-德語、英語-中文等）
- 數百萬句子對

**語言對示例（WMT 2023）：**
```
- English ↔ German
- English ↔ Chinese
- English ↔ Russian
- English ↔ Japanese
- English ↔ Czech
...
```

**評估方法：**
```python
# 自動評估
from sacrebleu import corpus_bleu

references = [["The cat is on the mat."]]
hypothesis = ["The cat is on the mat."]

bleu = corpus_bleu(hypothesis, references)
print(f"BLEU: {bleu.score:.2f}")

# 人類評估（Direct Assessment）
# 評估者對翻譯質量打分 0-100
```

**指標演進：**
```
傳統：BLEU
改進：METEOR, TER
現代：COMET, BLEURT（基於神經網絡）
```

#### 2.2 FLORES-200

**特點：**
- 200 種語言
- 專注低資源語言
- 相同內容的多語言平行語料

**應用：**
測試多語言 LLM 的翻譯能力，特別是小語種。

**評估示例：**
```python
from datasets import load_dataset

# 載入 FLORES
flores = load_dataset("facebook/flores", "eng_Latn-zho_Hans")

# 測試範例
source_text = "The quick brown fox jumps over the lazy dog."
# 英語 → 中文
target_text = model.translate(source_text, source_lang="en", target_lang="zh")

# 與參考翻譯比較
reference = "敏捷的棕色狐狸跳過懶狗。"
```

## 3. 文字摘要 (Text Summarization)

### 📋 主要基準

#### 3.1 CNN/Daily Mail

**基本資訊：**
- 新聞文章摘要
- 300K+ 文章
- 平均文章長度：~800 詞
- 平均摘要長度：~60 詞

**任務類型：**
- 抽取式摘要（從原文選句子）
- 生成式摘要（重新表述）

**評估指標：**
```python
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(
    ['rouge1', 'rouge2', 'rougeL'],
    use_stemmer=True
)

article = "..."
reference_summary = "..."
generated_summary = model.summarize(article)

scores = scorer.score(reference_summary, generated_summary)
print(f"ROUGE-1: {scores['rouge1'].fmeasure:.4f}")
print(f"ROUGE-2: {scores['rouge2'].fmeasure:.4f}")
print(f"ROUGE-L: {scores['rougeL'].fmeasure:.4f}")
```

**典型分數：**
```
BART:      ROUGE-1: 44.16, ROUGE-2: 21.28, ROUGE-L: 40.90
PEGASUS:   ROUGE-1: 44.17, ROUGE-2: 21.47, ROUGE-L: 41.11
GPT-3.5:   ROUGE-1: ~42, ROUGE-2: ~20, ROUGE-L: ~39
```

#### 3.2 XSum (Extreme Summarization)

**特點：**
- BBC 文章摘要
- 極簡摘要（通常一句話）
- 更強調抽象能力

**CNN/DM vs XSum 對比：**
```
CNN/DM：
文章：[800 詞新聞]
摘要：[60 詞，3-4 個要點]

XSum：
文章：[400 詞新聞]
摘要：[20 詞，單句概括]
```

#### 3.3 Multi-News

**特點：**
- 多文檔摘要
- 需要整合多個來源
- 測試資訊整合能力

```python
    >>> has_close_elements([1.0, 2.0, 3.0], 0.5)
    False
    >>> has_close_elements([1.0, 2.8, 3.0, 4.0, 5.0, 2.0], 0.3)
    True
    """
    # TODO: 實現此函數
```

**評估指標：Pass@k**
```python
def calculate_pass_at_k(n, c, k):
    """
    n: 總樣本數
    c: 通過的樣本數
    k: 選取的樣本數

    Pass@k = 至少有 1 個正確的概率
    """
    if n - c < k:
        return 1.0
    return 1.0 - (comb(n - c, k) / comb(n, k))

# 典型用法：生成 100 個解，計算 Pass@1, Pass@10, Pass@100
```

**典型性能（Pass@1）：**
```
GPT-4:         67%
GPT-3.5:       48%
Codex:         28%
CodeLlama-34B: 48%
```

## 5. 領域特化評估

### 5.1 醫療領域

#### MedQA

**基本資訊：**
- 醫學執照考試題
- 多選題（4-5 個選項）
- 涵蓋多個醫學學科

**示例：**
```
問題：
A 45-year-old man presents with chest pain radiating to the
left arm. ECG shows ST-segment elevation. What is the most
likely diagnosis?

A) Stable angina
B) Acute myocardial infarction
C) Pericarditis
D) Pulmonary embolism

答案：B
```

#### PubMedQA

**特點：**
- 基於 PubMed 醫學文獻
- 是非判斷題
- 測試生物醫學文獻理解

**性能基準：**
```
GPT-4:          ~75% (MedQA)
Med-PaLM 2:     ~85% (MedQA)
人類醫生基準：    ~87%
```

### 5.2 法律領域

#### LegalBench

**測試內容：**
- 法律推理
- 合同分析

- 法規解釋

**任務類型：**
```
1. 法律問答
2. 合同條款分類
3. 判決預測
4. 法律文檔摘要
```

### 5.3 金融領域

#### FinQA

**特點：**
- 財務報告問答
- 需要數值推理
- 結合表格和文字

**示例：**
```
財報表格：
| 項目     | 2022  | 2023  |
|---------|-------|-------|
| 收入     | 100M  | 120M  |
| 成本     | 60M   | 70M   |

問題：2023 年的利潤率比 2022 年提高了多少？

答案：需要計算
2022 利潤率: (100-60)/100 = 40%
2023 利潤率: (120-70)/120 = 41.67%
提高：1.67 個百分點
```

## 📊 自定義基準開發

### 🎯 為什麼需要自定義基準？

1. **業務特定需求**：通用基準無法覆蓋
2. **領域專業性**：專業術語和場景
3. **內部資料**：利用自有資料資產
4. **競爭優勢**：針對性優化

### 🔧 開發流程

#### 步驟 1：定義評估目標

```markdown
示例：客服聊天機器人評估

目標：
1. 準確理解客戶問題
2. 提供正確的解決方案
3. 保持友好的語氣
4. 在 3 輪對話內解決問題
```

#### 步驟 2：收集和標註資料

```python
# 資料格式設計
custom_benchmark = {
    "task_name": "customer_service_qa",
    "version": "1.0",
    "samples": [
        {
            "id": "cs_001",
            "category": "退貨政策",
            "user_query": "我想退貨，但已經超過 30 天了",
            "context": {
                "order_date": "2024-01-01",
                "current_date": "2024-02-15"
            },
            "reference_answer": "...",
            "evaluation_criteria": {
                "factual_accuracy": 1.0,  # 必須正確
                "tone": "friendly",       # 友好語氣
                "max_turns": 3            # 最多 3 輪
            }
        },
        # ... 更多樣本
    ]
}
```

#### 步驟 3：設計評估指標

```python
def evaluate_customer_service(response, reference, criteria):
    """自定義評估函數"""
    scores = {}

    # 1. 事實準確性（自動）
    scores['factual'] = check_facts(response, reference)

    # 2. 語氣（使用 LLM 評判）
    scores['tone'] = evaluate_tone_with_llm(response, criteria['tone'])

    # 3. 完整性
    scores['completeness'] = check_completeness(response, reference)

    # 4. 安全性
    scores['safety'] = check_safety(response)

    # 加權平均
    final_score = (
        scores['factual'] * 0.4 +
        scores['tone'] * 0.2 +
        scores['completeness'] * 0.3 +
        scores['safety'] * 0.1
    )

    return final_score, scores
```

#### 步驟 4：建立基準線

```python
# 測試多個模型建立基準
models = ['gpt-3.5', 'gpt-4', 'claude-3', 'custom-model']

baseline_results = {}
for model in models:
    scores = evaluate_model_on_benchmark(model, custom_benchmark)
    baseline_results[model] = scores

print("Baseline Results:")
for model, score in baseline_results.items():
    print(f"{model}: {score:.2%}")
```

### 📋 測試集設計原則

1. **代表性**：覆蓋實際場景分布
2. **多樣性**：不同難度、類型
3. **無偏見**：避免資料偏差
4. **可維護**：定期更新
5. **規模適中**：100-1000 個樣本起步

### ⚠️ 常見陷阱

| 陷阱 | 問題 | 解決方法 |
|------|------|---------|
| **過度擬合測試集** | 模型記住測試答案 | 定期更新、使用保留集 |
| **資料洩漏** | 測試資料混入訓練集 | 嚴格分離、時間切分 |
| **評估者偏差** | 標註不一致 | 多標註者、清晰標準 |
| **樣本不平衡** | 某些類別過多 | 分層採樣 |
| **過小的測試集** | 統計不可靠 | 至少 100+ 樣本 |

## 🎯 最佳實踐

### ✅ 應該做的

1. **組合評估**：通用基準 + 任務特定基準
2. **持續更新**：定期添加新樣本
3. **記錄版本**：追蹤基準變化
4. **公開分享**：促進社群發展（如適用）
5. **人類驗證**：定期進行人類評估

### ❌ 避免的錯誤

1. ❌ 只依賴單一基準
2. ❌ 忽視資料品質
3. ❌ 過度優化特定基準
4. ❌ 忽視實際應用場景
5. ❌ 不更新過時的基準
