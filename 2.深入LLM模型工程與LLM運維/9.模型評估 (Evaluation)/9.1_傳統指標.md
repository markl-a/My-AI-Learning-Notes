# 9.1 傳統指標與其限制

## 📊 概述

傳統 NLP 評估指標主要源自早期機器翻譯、文本摘要等任務。這些指標在特定場景下仍然有用，但在評估大型語言模型時面臨顯著的局限性。

## 1. Perplexity（困惑度）

### 📖 定義

Perplexity 衡量語言模型預測測試數據的能力，數值越低表示模型越「不困惑」，預測越準確。

**數學定義：**

```
PPL(X) = exp(-1/N * Σ log P(x_i | x_<i))
```

其中：
- `N` 是序列長度
- `P(x_i | x_<i)` 是模型對第 i 個詞的條件概率

### 💡 直觀理解

Perplexity 可以理解為：模型在每一步平均考慮多少個可能的詞彙選擇。

**例子：**
- PPL = 1：模型完全確定下一個詞（完美預測）
- PPL = 10：模型平均在 10 個詞之間猶豫不決
- PPL = 1000：模型非常不確定

### 🔧 計算示例（Python）

```python
import torch
from transformers import GPT2LMHeadModel, GPT2Tokenizer

def calculate_perplexity(text, model, tokenizer):
    """計算給定文本的 Perplexity"""
    encodings = tokenizer(text, return_tensors='pt')

    max_length = model.config.n_positions
    stride = 512

    nlls = []
    for i in range(0, encodings.input_ids.size(1), stride):
        begin_loc = max(i + stride - max_length, 0)
        end_loc = min(i + stride, encodings.input_ids.size(1))
        trg_len = end_loc - i

        input_ids = encodings.input_ids[:, begin_loc:end_loc]
        target_ids = input_ids.clone()
        target_ids[:, :-trg_len] = -100

        with torch.no_grad():
            outputs = model(input_ids, labels=target_ids)
            neg_log_likelihood = outputs.loss * trg_len

        nlls.append(neg_log_likelihood)

    ppl = torch.exp(torch.stack(nlls).sum() / end_loc)
    return ppl.item()

# 使用範例
model = GPT2LMHeadModel.from_pretrained('gpt2')
tokenizer = GPT2Tokenizer.from_pretrained('gpt2')

text = "The quick brown fox jumps over the lazy dog."
ppl = calculate_perplexity(text, model, tokenizer)
print(f"Perplexity: {ppl:.2f}")
```

### ✅ 適用場景

- **預訓練階段監控**：追蹤訓練損失下降
- **模型比較**：在相同數據集上比較不同模型
- **領域適應評估**：檢查模型對特定領域文本的熟悉度

### ⚠️ 局限性

1. **不反映生成質量**
   - 低 Perplexity 不保證生成的文本有意義
   - 模型可能過度擬合訓練分布

2. **無法評估創意性**
   - 創意寫作可能有較高的 Perplexity（因為更不可預測）
   - 不適合評估開放式生成任務

3. **缺乏語義理解**
   - 只衡量統計相似性，不評估語義正確性
   - 無法檢測事實錯誤

4. **對詞表敏感**
   - 不同模型的詞表不同，Perplexity 不可直接比較
   - 數值範圍受詞表大小影響

**示例：**
```
模型 A：PPL = 20（詞表 30K）
模型 B：PPL = 25（詞表 50K）
→ 無法直接得出 A 優於 B 的結論
```

## 2. BLEU Score

### 📖 定義

BLEU (Bilingual Evaluation Understudy) 是機器翻譯領域最常用的自動評估指標，通過比較生成文本和參考文本的 n-gram 重疊度來評分。

**數學定義：**

```
BLEU = BP × exp(Σ w_n log p_n)
```

其中：
- `p_n`：n-gram 精確度
- `w_n`：權重（通常均等：1/4）
- `BP`：簡短懲罰因子 (Brevity Penalty)

### 💡 核心思想

評估生成文本中有多少 n-gram 片段出現在參考文本中。

**例子：**

```
參考譯文: The cat is on the mat.
候選譯文: The cat the cat on the mat.

1-gram 精確度: 6/7 = 0.857 (7個詞中6個出現在參考中)
2-gram 精確度: 4/6 = 0.667
3-gram 精確度: 2/5 = 0.400
4-gram 精確度: 1/4 = 0.250
```

### 🔧 計算示例（Python）

```python
from nltk.translate.bleu_score import sentence_bleu, corpus_bleu
from nltk.translate.bleu_score import SmoothingFunction

# 單句 BLEU
reference = [['the', 'cat', 'is', 'on', 'the', 'mat']]
candidate = ['the', 'cat', 'the', 'cat', 'on', 'the', 'mat']

# 計算 BLEU-4（1-4 gram 均等權重）
score = sentence_bleu(reference, candidate)
print(f"BLEU-4: {score:.4f}")

# 分別計算不同 n-gram 的 BLEU
weights_1gram = (1, 0, 0, 0)
weights_2gram = (0.5, 0.5, 0, 0)

bleu_1 = sentence_bleu(reference, candidate, weights=weights_1gram)
bleu_2 = sentence_bleu(reference, candidate, weights=weights_2gram)

print(f"BLEU-1: {bleu_1:.4f}")
print(f"BLEU-2: {bleu_2:.4f}")

# 使用平滑技術避免零值
smooth = SmoothingFunction()
score_smooth = sentence_bleu(reference, candidate,
                              smoothing_function=smooth.method1)
```

### 📊 BLEU 分數解讀

| BLEU Score | 翻譯質量 | 說明 |
|-----------|---------|------|
| < 10      | 幾乎無用 | 翻譯幾乎不可理解 |
| 10-20     | 很差     | 可以看出一些含義 |
| 20-30     | 差       | 大致可理解，但有很多錯誤 |
| 30-40     | 尚可     | 可理解，有一些錯誤 |
| 40-50     | 良好     | 高質量翻譯 |
| 50-60     | 非常好   | 接近人類翻譯 |
| > 60      | 極佳     | 質量通常優於人類平均水準 |

### ✅ 適用場景

1. **機器翻譯評估**（最初設計目的）
2. **圖片描述生成**
3. **快速批量評估**
4. **模型開發過程中的相對比較**

### ⚠️ 局限性

#### 1. **同義詞問題**

```
參考: The weather is beautiful today.
候選A: The weather is nice today.       → BLEU 較低（但語義正確）
候選B: The weather is beautiful today.  → BLEU = 1.0
```

#### 2. **詞序不敏感**

```
參考: The dog bit the man.
候選: The man bit the dog.  → 可能獲得高 BLEU，但意思完全相反！
```

#### 3. **不適合評估對話和創意生成**

```
用戶: 今天天氣怎麼樣？
參考回覆: 今天陽光明媚，很適合出門。
候選回覆A: 天氣晴朗，溫度宜人。        → BLEU 低，但完全正確
候選回覆B: 今天陽光明媚，很適合出門。   → BLEU 高
```

#### 4. **需要高質量參考答案**
- 對話系統往往有多種正確回答方式
- 準備多個參考答案成本高

#### 5. **懲罰長文本**
- 長文本更難與參考完全匹配
- 過度簡短的輸出可能獲得不公平的高分

## 3. ROUGE Score

### 📖 定義

ROUGE (Recall-Oriented Understudy for Gisting Evaluation) 主要用於文本摘要評估，強調召回率（Recall）而非精確率。

### 🔢 主要變體

#### ROUGE-N（N-gram 重疊）

```python
ROUGE-N Recall = (參考摘要中匹配的 N-gram) / (參考摘要中總 N-gram)
ROUGE-N Precision = (參考摘要中匹配的 N-gram) / (候選摘要中總 N-gram)
ROUGE-N F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

#### ROUGE-L（最長公共子序列）

衡量候選摘要和參考摘要之間的最長公共子序列（LCS）。

#### ROUGE-S（跳躍二元組）

允許詞之間有間隔的二元組匹配。

### 🔧 計算示例（Python）

```python
from rouge_score import rouge_scorer

# 初始化評分器
scorer = rouge_scorer.RougeScorer(['rouge1', 'rouge2', 'rougeL'],
                                   use_stemmer=True)

reference = "The quick brown fox jumps over the lazy dog"
candidate = "The fast brown fox jumps over the sleepy dog"

scores = scorer.score(reference, candidate)

for key, value in scores.items():
    print(f"{key}:")
    print(f"  Precision: {value.precision:.4f}")
    print(f"  Recall: {value.recall:.4f}")
    print(f"  F1: {value.fmeasure:.4f}")
```

### 📊 BLEU vs ROUGE 對比

| 特性 | BLEU | ROUGE |
|------|------|-------|
| **核心指標** | Precision（精確率） | Recall（召回率） |
| **主要用途** | 機器翻譯 | 文本摘要 |
| **設計理念** | 避免生成不相關內容 | 確保覆蓋關鍵信息 |
| **懲罰方向** | 懲罰過長的輸出 | 懲罰遺漏關鍵信息 |
| **多參考答案** | 支持較好 | 支持較好 |

### ✅ 適用場景

1. **文本摘要評估**（抽取式和生成式）
2. **標題生成**
3. **關鍵信息提取**

### ⚠️ 局限性

與 BLEU 類似，加上：
- **過度重視字面匹配**：同義替換會降低分數
- **不評估流暢度**：拼湊的片段可能得高分
- **無法評估摘要的連貫性和可讀性**

## 4. 其他傳統指標

### 4.1 METEOR

**改進點：**
- 考慮同義詞匹配（WordNet）
- 考慮詞幹變化
- 重視詞序（通過分塊和懲罰）

**公式：**
```
METEOR = F_mean × (1 - Penalty)
Penalty = γ × (chunks / matches)^β
```

**優勢：**
- 與人類判斷相關性更高
- 對同義詞和變形更寬容

**劣勢：**
- 計算複雜度較高
- 依賴語言資源（WordNet）

### 4.2 CIDEr

**專門用於：** 圖像描述生成

**核心思想：** 使用 TF-IDF 加權 n-gram，突出獨特的描述內容

**優勢：**
- 考慮詞的重要性（而非一視同仁）
- 多參考答案支持好

### 4.3 BERTScore

**創新點：** 使用 BERT 嵌入計算語義相似度

**計算方法：**
```python
from bert_score import score

references = ["The weather is beautiful today."]
candidates = ["The weather is nice today."]

P, R, F1 = score(candidates, references, lang='en',
                 model_type='bert-base-uncased')

print(f"Precision: {P.mean():.4f}")
print(f"Recall: {R.mean():.4f}")
print(f"F1: {F1.mean():.4f}")
```

**優勢：**
- 捕捉語義相似性
- 對同義詞和改述更友好
- 與人類判斷相關性較高

**劣勢：**
- 計算成本高（需要運行 BERT）
- 仍然依賴參考答案
- 不評估事實性和推理能力

## 🔴 傳統指標在 LLM 時代的核心問題

### 1. **多樣性的懲罰**

LLM 的強項是生成多樣化的回答，但傳統指標偏好與參考答案字面相似。

```
問題: 解釋光合作用。

參考答案: 光合作用是植物利用光能將二氧化碳和水轉化為葡萄糖的過程。

LLM 回答: 綠色植物通過葉綠素吸收太陽能，將 CO2 和 H2O 合成有機物並釋放氧氣。

→ 語義完全正確，但 BLEU/ROUGE 分數較低
```

### 2. **無法評估推理能力**

```
問題: 如果所有的玫瑰都是花，而有些花會凋謝，那麼...？

回答A: 所有玫瑰都會凋謝。           → 邏輯錯誤，但如果與參考答案相似，得分可能高
回答B: 有些玫瑰會凋謝，但不能確定全部。 → 邏輯正確，但措辭不同，得分可能低
```

### 3. **忽略有害內容**

傳統指標無法檢測：
- 偏見和歧視性內容
- 有害建議
- 錯誤信息
- 幻覺（Hallucination）

### 4. **依賴高質量參考答案**

- 為開放式任務準備參考答案成本極高
- 創意任務（寫作、腦力激盪）沒有「正確答案」

---

## 📋 使用建議

### ✅ 應該使用傳統指標的場景

1. **封閉式任務**
   - 機器翻譯（有明確的對應翻譯）
   - 數據轉文本（如天氣報告生成）

2. **快速迭代階段**
   - 初期模型比較
   - 超參數調優

3. **作為補充指標**
   - 與其他評估方法結合使用
   - 提供量化基準

### ❌ 不應該依賴傳統指標的場景

1. **對話系統** → 使用人類評估或 LLM-as-judge
2. **創意寫作** → 人類評估
3. **推理任務** → 任務準確率
4. **開放式 QA** → 結合多種評估方法

---

## 🔄 進化方向

現代 LLM 評估正在從：

```
字面匹配 (BLEU/ROUGE)
    ↓
語義相似度 (BERTScore)
    ↓
任務準確率 (Benchmark Datasets)
    ↓
人類偏好對齊 (RLHF, ELO Rating)
    ↓
多維度評估 (Safety, Helpfulness, Truthfulness)
```

## 🎯 總結

傳統評估指標如 Perplexity、BLEU、ROUGE 在特定場景下仍有價值，但它們：

✅ **適合**：封閉式任務、快速比較、作為補充指標
❌ **不適合**：開放式對話、創意生成、推理評估

**核心教訓**：永遠不要只依賴單一指標，要根據具體任務選擇合適的評估方法組合。
