# 入門前置 — Voice / Audio AI

> ⚠️ **入門前置** — 讀完可進主 [README](./README.md)

## 目標讀者

**LLM 應用工程師,沒接觸過音訊處理 / 串流系統**。會 prompt、會接 OpenAI/Anthropic API,但一聽到「sample rate」「VAD」「barge-in」就卡。這份文件幫你建立最小可用心智模型,30 分鐘內把 voice bot 跑起來。

## 三層先決(缺哪補哪)

1. **Transformer 基礎** — Whisper、TTS 模型本質都是 encoder/decoder Transformer,先讀 [`../2.深入LLM模型工程與LLM運維/1.LLM 基礎與架構/`](../2.深入LLM模型工程與LLM運維/1.LLM%20基礎與架構/)
2. **Agent 概念** — Voice Agent 是 audio-version ReAct,STT 換成 audio→text 輸入,TTS 換成 text→audio 輸出,核心 loop 不變,先讀 [`../3.LLM應用工程/3.Agent/`](../3.LLM應用工程/3.Agent/)
3. **串流系統三選一** — WebRTC(低延遲雙向,瀏覽器/手機首選)/ WebSocket(server↔server 通用)/ SSE(單向 server push,LLM token 串流常用)。先懂一個就能上手。

## 5 個必懂音訊概念(1 分鐘速成)

- **取樣率(sample rate)**:8 kHz 電話 / 16 kHz STT 寬頻標準 / 48 kHz CD 音質。STT 模型多半吃 16 kHz mono PCM。
- **Mel spectrogram**:把波形轉成時間×頻率二維圖,Whisper 等模型實際吃這個。
- **VAD(Voice Activity Detection)**:判斷「有沒有人在說話」,常用 Silero VAD、WebRTC VAD。沒有 VAD 就是把空白也送進 STT,浪費 token、延遲爆掉。
- **Endpoint detection / turn-taking**:判斷「使用者講完了沒」,決定何時觸發 LLM 推理。是 voice UX 的核心難點。
- **Codec**:Opus(WebRTC 預設,壓縮率高)/ PCM(無壓縮,STT 友善)/ neural codec(EnCodec、SoundStream,LLM-native)。

## STT→LLM→TTS pipeline(1 分鐘速成)

```
麥克風 →[VAD]→ 音訊塊 →[STT 串流]→ 部分文字 →[endpoint?]→
完整 utterance →[LLM 串流 token]→ 文字塊 →[TTS 串流]→ 音訊塊 → 喇叭
```

三段都要 **串流**,任何一段等完整輸出 = 延遲爆炸。目標:**TTFA(首音延遲)< 800 ms**。

## 30 分鐘動手

用三個 API 拼最小 voice bot:**Deepgram**(STT 串流)+ **OpenAI**(LLM 串流)+ **Cartesia / ElevenLabs**(TTS 串流)。三個都有 WebSocket SDK,串起來不到 200 行 Python。先做能講話,再優化 barge-in。

## 名詞速查

| 詞 | 意思 |
|---|---|
| **WER** | Word Error Rate,STT 準度指標,越低越好 |
| **MOS** | Mean Opinion Score,TTS 自然度 1-5 分 |
| **TTFA / TTFB / TTFT** | Time To First Audio / Byte / Token,延遲指標 |
| **SIP / SDP** | 電話系統信令協定(接 Twilio / 電話線必懂) |
| **Barge-in** | 使用者打斷 bot 講話,bot 要立刻閉嘴 |
