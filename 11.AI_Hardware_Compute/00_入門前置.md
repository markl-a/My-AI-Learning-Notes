## 3 個必懂概念(1 分鐘速成)

- **Arithmetic Intensity** = FLOPs / Bytes。低於硬體的 FLOPs:頻寬比 → memory-bound(被 HBM 拖死);高於 → compute-bound。LLM decode 幾乎都是 memory-bound,這就是為什麼 batch、KV cache、speculative decoding 重要。
- **HBM vs FLOPs**:H100 有 ~3 TB/s HBM3,但 FLOPs:頻寬 ≈ 300:1。意思是搬 1 byte 的時間夠算 300 次浮點。所以「省顯存」常常比「省算力」更賺。
- **液冷為何不可避免**:B200 / GB200 單卡 ~1000–1200W,單機櫃 >120 kW,風冷物理上抽不掉這個熱通量(>30 kW/rack 就是極限),液冷(D2C、immersion)是 2025+ AI 機房的標配,不是噱頭。

## 15 分鐘動手

```bash
nvidia-smi                              # 看 GPU 型號、VRAM、功耗
nvidia-smi -q -d MEMORY,POWER,CLOCK     # 看細部:HBM 容量、TDP、時脈
```

```python
import torch
print(torch.cuda.get_device_properties(0))
x = torch.randn(1024, 1024, device="cuda", dtype=torch.bfloat16)
print(torch.cuda.memory_allocated() / 1e6, "MB")
```

接著用 `transformers` 載一個 70B 模型(`Meta-Llama-3.1-70B`,INT4 量化)看 VRAM,實際體會「為何 70B 在單張 H100 跑不動,要切兩張或量化到 4-bit」。

## 名詞速查

| 詞 | 一句話 |
|---|---|
| **HBM3E** | 高頻寬記憶體第三代強化版,~1.2 TB/s/stack,H200/B200 用 |
| **NVLink / NVSwitch** | NVIDIA 卡間互連,~900 GB/s,跨卡張量平行的命脈 |
| **TPU pod** | Google 把數千顆 TPU 透過 ICI 連起來的超算單元 |
| **Stargate** | OpenAI × Oracle × SoftBank 的 500 GW 級 AI 基建計畫 |
| **CoWoS** | TSMC 的 2.5D 封裝,把 GPU die 跟 HBM 包在一起;產能就是 AI 算力瓶頸 |
