# 15.Privacy_Confidential_AI 入門前置

> 本檔是進入 `15.Privacy_Confidential_AI/README.md` 之前的**橋樑文件**。
> Privacy AI 是三條技術線交織的混合領域,先把三條線各自定位清楚,再讀 deep-dive 才不會亂。

## 三條軸線 1 分鐘介紹

| 軸線 | 解決的問題 | 核心技術 |
|---|---|---|
| **DP (Differential Privacy)** | 「模型會不會洩漏單筆訓練資料?」 | 訓練時對梯度/輸出加噪聲,給出 (ε,δ) 數學保證 |
| **FL (Federated Learning)** | 「能不能不集中資料就訓練?」 | 資料留在本地,只交換模型梯度/參數 |
| **TEE (Trusted Execution Environment)** | 「能不能讓 host 看不見我在跑什麼?」 | 硬體加密記憶體 + remote attestation (SGX/TDX/SEV) |

**關鍵:三者互補,不互斥**。實務常見組合是「FL 訓 + DP 加噪 + TEE 跑 server-side aggregation」三層防護。讀論文時要先判斷它在哪條軸線、解的是哪層威脅。

## 先決條件

1. **會跑 SFT**: 知道 `Trainer.train()` 在做什麼;讀過 `peft` 或 `transformers` 的 fine-tune script 至少一次。
2. **知道 SGD**: 懂 batch gradient、learning rate;DP-SGD 就是在 SGD 每一步 clip 梯度 + 加 Gaussian noise,沒有這基礎讀不下去。
3. **知道對稱/非對稱加密**: AES vs RSA 一句話能解釋;TEE 章節會用到 attestation 流程裡的數位簽章。

不需要密碼學專業背景,但建議花 1 小時看 [Cryptography 101 by Christof Paar 第 1 講](https://www.youtube.com/watch?v=2aHkqB2-46k)。

## 為何重要

- **醫療**: HIPAA (US)、台灣個資法第 6 條對病歷敏感資料明文限制,不去識別化不准外送。
- **金融**: 各國 KYC/AML 規範資料跨境流通,銀行間想合作訓欺詐模型 → FL 是唯一合法解。
- **政府**: GDPR Art. 22 (自動化決策)、EU AI Act 2024 (高風險系統登記制) 已上路,2026 起全面執法。
- **企業**: NIST AI RMF 與 ISO/IEC 27090 (AI security) 開始被供應鏈合約要求。

去識別化做得不夠,2026 後直接被 fine 進骨子裡——這領域不是 nice-to-have。

## 60 分鐘動手:Flower + Opacus

第一階段:純 FL 跑 MNIST (Flower quickstart, ~20 分鐘)
```bash
pip install flwr[simulation] torch torchvision
git clone https://github.com/adap/flower.git
cd flower/examples/quickstart-pytorch
python sim.py   # 模擬 10 個 client + 1 個 server
```

第二階段:加上 DP-SGD (Opacus, ~40 分鐘)
```bash
pip install opacus
```
在 client 端 training loop 包上 `PrivacyEngine`:
```python
from opacus import PrivacyEngine
privacy_engine = PrivacyEngine()
model, optimizer, train_loader = privacy_engine.make_private(
    module=model, optimizer=optimizer, data_loader=train_loader,
    noise_multiplier=1.1, max_grad_norm=1.0,
)
# 訓練後印 ε:
print(privacy_engine.get_epsilon(delta=1e-5))
```
跑通後你就同時觸過 FL + DP 兩條軸線,後面讀 paper 都有錨點。

## 名詞速查

- **(ε, δ)-DP**: 給定鄰近資料集 D, D',演算法輸出分布滿足 `P(M(D)∈S) ≤ e^ε · P(M(D')∈S) + δ`。ε 越小隱私越強,業界 ε∈[1, 10] 算合理。
- **Secure Aggregation**: FL server 看不見單一 client 的梯度,只看得到加總——靠 secret sharing / homomorphic mask 達成。
- **RDP Accountant (Rényi DP)**: 比起原始 (ε, δ) 組合定理更緊,Opacus 預設用 RDP 追蹤隱私預算。
- **Attestation**: TEE 證明「我真的是 Intel SGX/AMD SEV 而非偽造環境」的數位簽章流程,client 驗章後才送機密資料進去。
- **SGX / TDX / SEV**: 三種主流 TEE——SGX (Intel, enclave 細粒度)、TDX (Intel, 整個 VM)、SEV (AMD, 整個 VM 加密)。NVIDIA H100/H200 也已支援 Confidential Compute。
