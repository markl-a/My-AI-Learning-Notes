## VLA(Vision-Language-Action)1 分鐘速成

VLA = **VLM 後端 + Action Head**。輸入是相機影像 + 語言指令,輸出是機械臂關節角度或末端位姿。
為何 **diffusion / flow matching 適合 action**:動作軌跡是多模態分佈(同一個任務有很多種合理走法),回歸 MSE 會學成「平均」(=動作糊掉、抖動);diffusion 直接建模整個分佈,輸出乾淨且多樣。π0、RDT-1B、Octo 都走這條路。

## Computer Use 同源

你已經會用 LLM agent 寫 GUI 自動化(Claude Computer Use、Anthropic computer-use-demo)。**VLA 就是「會動的 GUI agent」**:
- GUI agent:看螢幕截圖 → 輸出 `click(x, y)` / `type(...)`
- VLA:看相機畫面 → 輸出 `joint_angles[7]` / `gripper_state`

同一個套路:perception → planning → low-level action。差別只在動作空間從像素座標換成關節空間,且需要考慮物理連續性。這個觀念橋接過去,後面學 VLA 會快非常多。

## ACT(Action Chunking Transformer)簡介

ACT(Stanford ALOHA 提出)的關鍵 insight:**不要一步一步預測動作,而是一次預測一段(chunk)**,通常 ~50–100 步。
- 為何不 step-by-step:逐步預測會累積誤差(compounding error),且對 teleop 採集的非馬可夫資料不友善。
- 為何 chunk 有效:給模型「動作預謀」的空間,降低高頻抖動,且推論頻率可以遠低於控制頻率(模型 10 Hz、控制 100 Hz)。
- 後續所有主流 manipulation policy(Diffusion Policy、π0、RDT)幾乎都採 chunking。

## 30 分鐘動手

**LeRobot quickstart**(Hugging Face 出的開源機器人學習框架):

```bash
pip install lerobot
# 用 SO-100(便宜的 6-DoF 手臂,~300 USD)或先跑模擬
python -m lerobot.scripts.train policy=act env=aloha_sim_transfer_cube
```

純沒硬體也可以:LeRobot 內建 ALOHA / PushT / Xarm 的 sim 環境,跑 ACT 或 diffusion policy 在 GPU 上半小時就能看到收斂。
